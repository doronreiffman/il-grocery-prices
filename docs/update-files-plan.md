## What ships

A third collecting mode, `poll`: `{"mode": "poll", "chain": "<slug>", "kinds": [...]}` runs the existing run loop for the update kinds a chain polls (`Chain.polled`), stores what is not yet stored, and writes a manifest `<chain>-<HHMMSS>Z-poll-<4 hex>.json`. Every run's manifest gains `other_days`. A Shufersal poll starts from its current pass (`collector.pages.passes`), so a kind read several times a day is read as a series of readings, each joined across runs by ruling R37's rules. The 11:48 check judges the morning from `main` and `retry` runs only, and, while the poll switch is on, judges the day before's update files (`update_day` in its record): one email for a name a poll tried and did not store, or a kind no poll read all day. A poll run that stops a chain emails at once. The template gains a `PollScheduleState` switch and 27 polls for Rami Levy, Yochananof, Osher Ad and Carrefour; Shufersal's twelve come in a held-back task.

## What q24's merged code changed from what the design assumed

The design was written before q24 (ruling R38) merged into this branch (merge 3f2b69e). Where it differs, this plan builds on the code as it is:

- **The failed page tries have names now.** What sections 1 and 4 call "the list of failed page tries" is the manifest's `timeouts` (each `{"kind", "page", "attempt", "seconds"}`), and each page record carries `tries`. A Shufersal poll's manifest carries both, unchanged; neither the passes nor the update day reads them (as R38 has the check read neither).
- **Where the retry lives.** Section 3's "`_read_page`" reaches the tries through `_page_body`, which asks the run's time check before the 10 s pause and again after it (R38 as built, the owner's confirmation of 2026-11-07). Price and Promo pages get it with no change. A slow spell can cost a pass's run up to about 140 s more than section 6's durations count; the worst case (900 s a run) does not move.
- **`run.py`'s `_paged`** hands the listing `on_timeout` beside `starts` and `on_page`; the passes rule plugs into `starts` alone. The q21 mutation that quotes the `starts` line is re-pointed (Task 2).
- **`RunResult` already gained `timeouts`**, so `test_manifest_bytes` lists `"timeouts": []`; `other_days` joins it.
- **`tests/test_replay.py` holds q24's 2026-11-06 replay**, whose fake network serves a route list in turn and whose source's `sleep` moves the run's clock: Task 5's Promo replay uses the same machinery.
- **The baseline.** Section 8 quotes 1,059 mutations at 8a8bc00. On this branch at 3f2b69e, measured 2026-11-07: 1,367 tests pass, coverage 99.83% (`collector` and `src/basket`), 1,092 mutations, none stale.
- **`Http` raises `HttpTimeout`** on a socket timeout; only Shufersal's adapter asks again. An NCR or Carrefour poll whose listing times out ends `listing failed: …` as their runs do today.

## Where the design leaves room, this plan decides

- **Names.** `Chain.polled`; `RunResult.other_days` (manifest `other_days`: `{"YYYY-MM-DD": count}`); `collector.pages.Pass`, `passes`, `pass_start`; `collector.names.hour_of`; `collector.check.MORNING`, `stopped_alert`, `judge_update_day`, `check_day(..., polled=)`; the check record's `update_day` with `day` and `chains`, each chain's `polls`, `passes` (per kind `complete`, `out_of_order`, `open`), `missing`, `not_tried`, `by_hour`, `failed`; the environment variable `POLL_SCHEDULE_STATE` and `Config.polls_on`; the check event's `update_day` (Question 2); `handler.poll_message`; the template's events `Poll<Chain><HHMM>`.
- **Texts.** The update day's two alerts, `<slug>: <n> update file(s) a poll run tried on <day> and did not store: <up to ten names>[, and <n> more (the check record lists them all)].` and `<slug>: no poll run read the <Price list | Price and Promo lists> in full on <day>.`; a poll's stopped email as Task 4 gives it.
- **A poll event without `kinds` is refused.** The design says every poll event names its kinds; a default of `polled` would hand Shufersal both kinds in one run.
- **`other_days` is on every run's manifest**, main and retry included: section 7, step 4 reads it from the morning's main runs. It counts distinct names of the kinds asked for, per Israel date other than the run's.
- **Passes leave out a run whose listing was never read** (`listing_read_at` null: stopped before it, or a failed read of the earlier manifests): it read no page, so it can neither complete nor end a pass. A blocked run is left out, as the design says.
- **After a pass read in full or ended by a page out of order, the next run starts `Start()`**, with no detour: section 3's "otherwise a fresh pass from page 1".
- **The record names a pass a page out of order ended** (`out_of_order`) beside the complete ones and the open one, so a pass lost to disorder shows.
- **`not_tried`** counts, per update kind, the distinct names in any poll's `not_attempted` that are not stored and not in `missing`. **`by_hour`** keys are `"00"` to `"23"`, and `"unknown"` for a name whose time the hour cannot be read from.
- **The morning filter is one mutation, not two.** Section 8 names "a poll's `not_attempted` name raises `missing` at 11:48" and "a blocked poll silences R37's reason". Once the morning reads `main` and `retry` runs only, no single break makes a blocked poll silence R35 or R37 (both read retry runs' blocks alone), so the second is a test that pins the rule and the filter's one mutation is caught by the first and by the R36 test.
- **A poll's stopped email** goes when this run latched the chain (`blocked` set and not `stopped earlier`) and the state says stopped and not alerted; the chain is then marked alerted (R26). A failed publish fails the invocation and marks nothing, so the 11:48 check sends it again.
- **Shufersal's schedules and `polled`** wait for Task 10 (Question 3).
- **The replay's pace:** 42.0 s a Promo page (2026-11-06's PromoFull median, 41.75 s, rounded), 0.5 s a file (the design's "about 0.6 s"; a value exact in binary keeps the clock's sums exact), 13 of a page's 20 rows dated the day (279 of 418 stores' Promo on 2026-11-01, about 12.7 a page).

**Interfaces:**
- Consumes: `read_in_full`, `start_for`, `unread`, `has_pages`, `_records`, `Start`, unchanged.
- Produces (in `collector.pages`):

```python
@dataclass
class Pass:
    """One reading of an update kind's list by the day's poll runs (ruling R39)."""
    runs: list[dict]           # the pass's poll manifests, in listing_read_at order
    read_by: list[str] | None  # read_in_full(runs, kind): the runs that read the list in full; None when the pass did not
    out_of_order: bool         # its last run recorded a page of the kind out of order

    @property
    def open(self) -> bool: ...  # not read in full and not ended by a page out of order: the pass the next run carries on

def passes(manifests: list[dict], kind: str) -> list[Pass]: ...
def pass_start(manifests: list[dict], kind: str, stored: set[str]) -> Start: ...
```

- The rule:
  1. The runs that make passes: manifests with `mode` `"poll"`, `kind` in `kinds`, `blocked` null and `listing_read_at` not null, in order of `datetime.fromisoformat(listing_read_at)`.
  2. Each run joins the current pass. After it joins, the pass ends when `read_in_full(<the pass's runs>, kind)` is not None, or when this run recorded a page of the kind with `in_order` false; the next run begins a new pass. Runs left at the end make the last pass, open.
  3. `pass_start`: when the last pass is open, `start_for(<its runs>, kind, stored)` (a resume at its furthest page, detours to its failed files' pages); otherwise (no pass, or the last read in full or ended out of order) `Start()`.
