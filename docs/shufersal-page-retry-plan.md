# Shufersal: a listing page that times out is asked again (implementation plan)

Grade: production (live collector)

What ships: `Http` raises `HttpTimeout`, an `HttpError`, when a request passes its socket wait. The Shufersal adapter asks a listing page whose request timed out for it again, up to two more times, pausing 10 s before each and asking the run's time check after the pause, for every listing page it reads (a kind's pages, detours, steps back and the expired-link refresh). A page read on a later try records how many tries it took (`tries`); every timed-out try of the listing is kept in the manifest (`timeouts`) and logged at WARNING; a page whose three tries all time out ends the run with `listing failed: <kind> page <n> timed out on 3 tries: …`. The check, the schedules, the 60 s wait, the 90 s time rule, the resume and other chains do not change.

Tasks:

1. `Http` tells a timeout apart (`HttpTimeout`)
2. The Shufersal adapter asks a timed-out listing page again
3. The run loop keeps the failed tries in the manifest and logs the try
4. The check unchanged, pinned; 2026-11-05 and 2026-11-06 replayed
5. The docs: ruling R38, what changed, and three parked wording fixes
6. Full test run, coverage and the full mutation check
7. The whole-branch review

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Shufersal listing page that times out costs its run one wait and a pause, not the rest of the run, and every try is on the record.

**Architecture:** `Http` only classifies (a timeout becomes `HttpTimeout`) and still never retries. The tries live in the Shufersal adapter's one page request (`_read_page`, reached through `_pages` and `_PageReader` by the listing and the refresh alike), which also logs each failed try and reports it through a new `on_timeout` callback beside `on_page`. The run loop records what it is told (`tries` rides on the page record it already keeps; `timeouts` is a new manifest list) and the check reads neither.

**Tech Stack:** Python 3.13 standard library (`urllib`, `logging`, `dataclasses`, `time`); pytest, pytest-cov. No new dependency.

**Spec:** `docs/shufersal-page-retry.md` (approved by the owner on 2026-11-06; its "Calls" are decided: build them as written). Read it first, in full, then `docs/collector.md` ("How a morning runs", "Testing and shipping") and rulings R36 and R37 in `docs/collector-plan.md` ("Rulings made during the build").

## Where the design leaves room, this plan decides

- **Names:** `HttpTimeout`, `PAGE_TRIES`, `RETRY_PAUSE`, `PageRead.tries`, `PageTimeout` (fields `kind`, `page`, `attempt`, `seconds`: `try` is a Python keyword), the callback `on_timeout`, the manifest list `timeouts`.
- **Texts:** the adapter's error `<kind> page <n> timed out on 3 tries: <the last try's error>` (the run loop adds `listing failed: `); a time stop before a later try, `before try <n> of page <p> of the <kind> listing` (before the first try the text stays `before page <p> of the <kind> listing`, which tests pin today); the WARNING and INFO lines as Tasks 2 and 3 give them.
- **The adapter logs each failed try, not the run loop:** the line needs `PAGE_TRIES` and `RETRY_PAUSE`, which are the adapter's, and the refresh has no callback.
- **A refresh's failed tries are logged, not listed in `timeouts`:** the design's list is "reported by the adapter as it reports pages", and the refresh reports no page (`_fresh_link` passes no `on_page`, `src/collector/sources/shufersal.py:122`); a download has no callback (`Source.download`'s parameters are pinned by `tests/test_chains.py:132`), and an entry from a refresh could not be told from a listing page's. When every try of a refresh page fails, the file's failure names the page and the tries.
- **The adapter's sleep** is a constructor argument, `time.sleep` by default, as `Http`'s is. The 2026-11-06 replay joins `tests/test_replay.py`, beside 2026-11-05's.
- **Task order:** the 2026-11-05 replay's fake network changes in Task 2, with the adapter: the replay fails the moment a timed-out page is asked again (its retries' second request is served), and its source would call the real `time.sleep`. Its `timeouts` assertions come in Task 4, once Task 3 writes the list. The check's pins (the design's "Testing", the check) are tests only and join the replays in Task 4.

### Task 2: The Shufersal adapter asks a timed-out listing page again

**Files:**
- Modify: `src/collector/sources/__init__.py` (`PageRead.tries`, `PageTimeout`, `PagedSource.listing`'s `on_timeout`, the module docstring)

- Modify: `scripts/mutation_check.py`

**Interfaces:**
- Consumes: `HttpTimeout` (Task 1).
- Produces (in `collector.sources`):

```python
@dataclass(frozen=True)
class PageRead:
    ...                # the eight fields as today, in order
    tries: int = 1     # the requests it took to read the page: 1, or 2 or 3 when earlier tries timed out

@dataclass(frozen=True)
class PageTimeout:
    """One request for a listing page that passed the socket wait, as a paged adapter reports it."""
    kind: str
    page: int
    attempt: int       # the try's number, from 1
    seconds: float     # how long the try waited, rounded to 0.1 s (Http's 0.5 s pause included)

class PagedSource(Source):
    def listing(self, http, kinds, short_of_time=never_short, starts=None, on_page=None,
                on_timeout: Callable[[PageTimeout], None] | None = None) -> Iterator[Listed]: ...
```

- In `collector.sources.shufersal`: `PAGE_TRIES = 3`; `RETRY_PAUSE = 10.0` (seconds); `ShufersalSource.__init__(self, now=_utc_now, timer=time.monotonic, sleep: Callable[[float], None] = time.sleep)`; `listing` takes `on_timeout` as `PagedSource.listing` does (`test_every_adapter_takes_the_interfaces_parameters` compares them).
- The rule, for every listing page request the adapter makes (a kind's pages, detours, steps back and the expired-link refresh's pages, which all read through `_pages` and `_PageReader`):
  1. The first try asks the time check, then sends the request. A second or third try first sleeps `RETRY_PAUSE`, then asks the time check, then sends. Short of time: `OutOfTime`, no request; its text is `before page <p> of the <kind> listing` before the first try, `before try <n> of page <p> of the <kind> listing` before a later one.
  2. The timer is read twice a request, at its start and at its end, and nowhere else: a try's seconds are that request's alone.
  3. A try that raises `HttpTimeout` is reported to `on_timeout` as `PageTimeout(kind, page, n, round(seconds, 1))` and logged, then the next try follows. The refresh reports to no one, as it reports no page, and logs all the same.
  4. Any other `HttpError`, a `Blocked`, and a page served that does not read as the listing (`ListingUnreadable`) are raised at once, whatever try they come on.
  5. After the third timeout: `HttpError(f"{kind} page {page} timed out on {PAGE_TRIES} tries: {last}")`, `last` the third try's `HttpTimeout`, chained from it. No page record for it, and no pause after the last try.
  6. A page read on try n: its `PageRead` has `tries=n` and `seconds` that try's request alone.
  7. Each failed try logs one line at WARNING on `logging.getLogger("collector.sources.shufersal")`: `shufersal PriceFull page 7: try 1 of 3 timed out after 60.5 s; again in 10 s`, and on the last try `shufersal PriceFull page 7: try 3 of 3 timed out after 60.5 s`.
