# A time-stopped poll's unreached names (implementation plan)

Grade: production. The collector is live, and every file it stores is locked for ten years.

Status: draft of 2026-11-08, written by Opus 5.5 from the approved design; approved by the owner the same day (no questions open); building.

## What ships

A poll run of Rami Levy, Osher Ad, Carrefour or Yochananof that stops on its own time check reads the rest of its listing from memory, taking nothing: each name of its day and of the kinds asked for joins `listed`, and `not_attempted` unless it was stored before the run. No request, download or store follows the stop. A fault met there never reads as a time stop: a block latches the chain as the loop would, and anything else fails the invocation with `unexpected error: …` in the manifest. Main and retry runs and every Shufersal run are unchanged, and so is the morning's judgement. The next morning's check keeps the update day's never-tried names by name (`not_tried`), leaves out the names a morning run listed, and emails them in the chain's `missing` alert beside the names a poll tried and failed, for a kind with no page records; Shufersal's stay counted until its polls are designed. Ruling R40.

**Goal:** a poll of the four quick chains that stops on time names every file of its day it listed and did not reach, and the next morning's check emails each update file of the day that no run stored, with not one request more to any portal.

**Architecture:** no new module, field or alert kind. `_Run._take`'s classification of a row moves into `_Run._listed`, which the take and a new `_Run._drain` share; `_Run.collect`'s `except _Stop` calls the drain under four conditions. `collector.sources`' docstring gains the rule the drain rests on, and a test per adapter pins it. `check._judge_updates` changes its `untried` set, keeps `not_tried` as names, and folds the emailed names into the one `missing` sentence (`check._lost_text`). The handler, the template, the schedules and the switches do not change.

**Tech Stack:** Python 3.13 standard library; pytest, pytest-cov, cfn-lint (CI's pins). No new dependency.

**Spec:** `docs/unreached-names.md` (approved by the owner on 2026-11-08: question B poll runs only, A email the quick chains' untried names, E Shufersal decided with Task 10, all as recommended; D the other way, q23's manual polls first). ## Where the design leaves room, this plan decides

- **Names.** `_Run._listed(item) -> str | None`, the take's classification (kind asked for; the run's day, else `other_days`; first sighting), which appends the name to `listed` and returns the stored name, or None for a row it does not list. `_Run._drain(listing)`. `check._lost_text(slug, day, failed, untried)` in place of `_unstored_text`. Test names as the tasks give them.
- **The page record stays the take's.** `_take` keeps setting `taken_through` (`src/collector/run.py:216-218`) before it calls `_listed`; the drain shares the classification only (`run.py:219-228`; each caller then tests `self.stored`, which completes the design's `run.py:219-230`), so a drained row moves no page record. A paged listing is not drained anyway.
- **A latch that cannot be written during the drain** reads as it does in the loop: `latch not written: …` in `error`, the store's exception raised. The design's "any other exception becomes `unexpected error: …`" applies to what the listing raises, not to the latch's own failure, which `_latch` has already recorded (`run.py:310-312`).
- **The sentence** (Call 10): `<slug>: <n> update files listed on <day> and not stored (<k> tried and failed, <m> never tried: a poll stopped on time before reaching them): <up to ten names>.` with `update file` for one, `reaching it` when one was never tried, a zero part left out, both parts' names sorted together, and beyond ten `, and <n> more (the check record lists them all)` as today (`check.py:230-234`).
- **The record.** `missing` keeps the names a poll tried and failed, as today. `not_tried` holds every update kind's untried names, a paged kind's included (counted, not emailed: Question E). The alert's names are `missing` and the `not_tried` names of each kind with no page records that day.
- **The five tests the design names** ("Tests and mutations", first bullet) are parametrized over `main` and `poll` on `POLLING` with kinds `("Price", "Promo")`, so their listings change from full-file names to update names in both modes; the `main` expectations are today's with the names swapped.

Entry 762 is re-anchored and renamed "not_tried left empty (q23 update day)". A Carrefour break joins NCR's for the adapters' rule (the design names NCR's alone), and the drain's latch failure has a test and a break of its own.
- **Ruling R39's lines** 368, 370 and 377 of `docs/collector-plan.md` keep their text as built and each gains a parenthetical, "since ruling R40 …", as the 2026-11-01 Task 11 entry gained one for R38. `docs/update-files.md`'s approved lines gain dated addenda, the approved text kept.

## Review Focus

1. **A fault in the drain never reads as a time stop.** A `RuntimeError` after the stop fails the invocation with `unexpected error: RuntimeError: …` in the manifest; a block latches the chain and a poll emails at once; a latch that cannot be written keeps `latch not written: …` and fails the invocation; `OutOfTime` ends the drain quietly. Tests in Task 1 (`test_a_fault_in_the_drain_fails_the_run_and_says_why`, `test_a_block_in_the_drain_latches_the_chain`, `test_a_block_in_the_drain_whose_latch_cannot_be_written_says_so`, `test_the_drain_ends_at_out_of_time_with_what_it_had`, and `tests/test_handler.py`'s `test_a_block_met_while_a_stopped_poll_lists_the_rest_emails_at_once`).
2. **Main, retry and Shufersal runs as before.** The five time-stop tests' `main` cases, the block and unreadable-listing tests in both modes, a paged listing in `poll` mode (`test_a_paged_listing_is_not_drained`), and the Shufersal replays (`tests/test_replay.py:99`, `225`, `325`, `375`), whose run-side assertions do not change.
3. **No request after the stop.** The drain downloads nothing (`source.downloaded` and the stored bodies in every Task 1 test), and the two adapters make no request after their first row (Task 2).
4. **The update day reports each loss once.** A name a later poll stored drops out; a name the morning listed is never reported again; a name failed by one poll and left untried by a later one is in `missing` only; a paged kind's untried names are counted, not emailed (the line Task 10 inherits). **Interfaces:**
- Consumes: `OUT_OF_TIME`, `PagedSource`, `Blocked`, `OutOfTime`, `_latch`, `_other_day`, unchanged.
- Produces:
  - `_Run._listed(item: Listed) -> str | None`: the body of today's `_take` from its kind filter to its `listed.append` (`run.py:219-228`): a kind not asked for, None; a name of another day, counted by `_other_day`, None; a name seen already in this run, None; otherwise the name is added to `seen` and `listed` and returned. It raises nothing.
  - `_Run._take(item)`: the `taken_through` step as today, then `name = self._listed(item)`; None or a name stored before the run returns; otherwise fetch and store as today.
  - `_Run._drain(listing: Iterator[Listed]) -> None`: asks `next(listing)` until the listing ends. Each row goes through `_listed`, and a name it returns that is not in `self.stored` is appended to `not_attempted`. `StopIteration` and `OutOfTime` end it with what it had. `Blocked` calls `_latch(str(block))` and ends it when the latch's `_Stop` comes back; a latch that cannot be written raises as in the loop. Any other exception sets `error` to `f"unexpected error: {type(exc).__name__}: {exc}"` and is raised. No download, store, state write other than the latch, time check or page record.
  - `_Run.collect`: `listing = None` before its `try`; its `except _Stop` calls `self._drain(listing)` when `self.result.error == OUT_OF_TIME`, `self.result.mode == "poll"`, `listing is not None` and `not isinstance(self.source, PagedSource)`. `unparsed` is not read after a drain.
  - The module docstring: the time-stop sentences (`run.py:20-25`) gain the drain (a poll run whose listing does not page reads the rest of it after its own time stop, taking nothing; a main or retry run, a paged listing and any other stop do not); the result paragraph's sentence on the names the listing had not yet given (`run.py:38-39`) is rewritten by mode and by paging (for a poll run of a listing that does not page, `listed` holds every name of the day and the kinds asked for that the listing gave and `not_attempted` every such name not stored before and never tried; for a main or retry run and every Shufersal run, the names the listing had not yet given are in none of them, and the retry run, or the next pass, lists them). `RunResult`'s docstring (`run.py:75-76`): `unparsed` is 0 on every run that stopped, a drained poll's included, and final only on a run whose own loop read the listing to its end.
